# 习惯与口径积累（Accumulation）

任务交付 ≠ 结束。每一次任务都会暴露"使用者的判断习惯"和"被确认过的专业口径"；这两类资产必须沉淀，否则同类任务每次从零开始、同类错误反复出现。

## 一、三层沉淀，位置不同

| 层 | 内容 | 存放位置 | 谁可写 |
| --- | --- | --- | --- |
| ① 使用习惯 | 受众常模、页数、确认节奏（哪些环节必须停）、被使用者纠正过的判断类型 | 个人 `ppt-profile.md` 的"工作方式/经验反馈"区 | 使用者确认后，AI 代记 |
| ② 专业口径库 | 某主题的**规则结构树**（分类轴、全集、例外、术语、关键阈值）、来源核对日、律师确认日 | 使用者工作目录的 `口径库/<主题>.md`（与 profile 同处；不进公共 Skill 目录） | 只有使用者（律师）确认过的条目可写入"已确认"区 |
| ③ 反例库 | 交付后被指出错误的页面/口径/原因与规避法 | 同上 `口径库/_反例.md` 或 profile 内 | 收到使用者/复核者反馈后记录 |

## 二、口径库条目模板

```markdown
# 口径：<主题>（例：CFIUS 管辖与强制申报）

## 规则结构树（先核对再生成用）
- 分类轴：……
- 全集：……（含子集与例外）
- 关键阈值/期限：……
- 术语对照：规则原文词 → 中文常用译（注明非官方）

## 记录
- 来源与核对日：……
- 律师确认日：……  确认人：……
- 未决点：……
- 修正记录：旧口径 → 被推翻原因 → 新口径（保留旧版，不覆盖）
```

## 三、读取时机（在生成之前）

1. **P0 前置 briefing 时**：查 `口径库/` 是否已有同主题条目。
2. 有 → 该主题进入**核对模式**：把条目中的结构树当作骨架，任务只做增量核对（法规是否更新、本案事实是否落入哪个分支），**不从零生成**，也不许把已确认口径改回"语感表述"。
3. 无 → 正常走"规则结构还原草稿 → 使用者裁决"，裁决通过后再考虑是否沉淀为新条目。

## 四、写入条件（防止污染）

- 只有**使用者（或其指定复核律师）明确确认**后的口径能进入"已确认"区；
- AI 生成的还原草稿若未被确认，只能放草稿区或留在任务的 review-checklist，不得冒充已确认口径；
- 修正必须先留"旧口径 + 原因"，禁止静默覆盖；
- 反例条目一句话讲清：哪页/哪句被批、根因（漏类别 / 错分轴 / 自造术语 / 翻译改变义务）、下次怎么防。

## 五、写入时机（自动提醒）

任务交付并收到使用者反馈后，AI 主动提示："本次是否沉淀：①使用习惯更新 ②<主题>口径库新增/修订 ③反例条目？" 使用者点头即写；使用者未回应默认不写已确认区。

## 六、目标状态

同一用户、同一大类任务（如"境外投资审查""出口管制""制裁"）第二次做时，P0/P2 的确认负担应明显下降：结构可直接给"上次锁定骨架的变体"，口径先核对、只改增量。这就是把"纯手感"变成"可迁移、可复核"的资产。
