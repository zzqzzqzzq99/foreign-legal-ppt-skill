# 涉外法律检索规则

## 1. 先固定检索边界

在开始检索前记录：法域、主题、相关主体与交易、时间范围、资料截止日、目标受众以及需要回答的业务问题。法域或时间范围不明确且会改变结论时，先询问用户。

## 2. 法源优先级

优先寻找并核验：

1. 宪法、条约、法律、法规及其官方修订文本；
2. 主管机关发布的规则、决定、指南、FAQ、申报表和正式数据库；
3. 法院或有权裁判机构的判决、案卷和程序记录；
4. 立法材料、监管说明和正式执法公告；
5. 权威二级资料，例如专业数据库、学术出版物和可靠律师事务所分析；
6. 新闻、博客和聚合内容，仅用于发现线索或补充背景。

存在官方英文原文时，不以中文翻译代替核验。使用非官方翻译时明确标注，并保留原文术语。网页摘要、搜索摘要和 AI 转述不能单独支撑关键法律结论。

## 3. 先建立议题地图

检索前先把主题拆成待回答问题，避免模型只围绕最容易找到的资料写作。议题地图至少考虑：

- 规则为什么存在、由谁执行以及适用对象；
- 管辖连接点、触发条件、门槛、例外和豁免；
- 申报或合规程序、材料、期限、费用及中止条件；
- 主管机关的调查、信息要求、裁量和救济权限；
- 违法、迟延或交易结构不当的后果；
- 代表性案例、执法趋势和案例适用边界；
- 对中国企业的交易文件、时间表、治理、数据、供应链和沟通影响；
- 管理层当前可以选择的方案、前置动作和需外部律师确认的问题。

这是一份覆盖检查表，不是固定目录。对每项标注“纳入正文、纳入附录、不适用、资料不足或待用户确认”，并说明理由。用户提出的核心问题必须能在议题地图中定位。

## 4. 时效和法律状态

对每项关键规则核对：

- 发布机关及其权限；
- 现行、废止、修订、拟议或过渡状态；
- 发布、生效、适用和最后核验日期；
- 联邦、州、省或其他地域层级；
- 强制规则、执法政策、解释指南或非约束性建议；
- 是否存在后续修订、判决、上诉或监管更新。

“截至某日有效”必须有实际检索记录支撑。无法核验时写明限制。

## 5. 案例和执法事件

案例记录至少包括：案件或事件名称、法院或机关、案号或公告编号、日期、程序阶段、核心事实、争点、裁判或处置、后续进展及与本项目的关系。

区分当事人主张、监管机关指控、法院认定、和解条款和作者评论。不要把未决案件写成已确立规则，也不要从单一案例推出普遍结论。

## 6. 来源台账

为实质性判断维护台账，建议字段如下：

| 字段 | 内容 |
| --- | --- |
| ID | 稳定编号，例如 S-01 |
| 命题 | 该来源支持的具体陈述 |
| 法域 | 国家、地区和层级 |
| 来源类型 | 法律、法规、判决、指南、执法公告或二级资料 |
| 发布机关 | 法院、监管机关或出版机构 |
| 标题与编号 | 官方标题、案号或规则编号 |
| 法律状态 | 现行、拟议、废止、上诉中等 |
| 日期 | 发布、生效及最后核验日期 |
| 定位 | 条款、段落、页码或章节 |
| 链接 | 直接链接，不使用搜索结果页 |
| 用途 | 将用于哪一页、支持何种结论 |
| 限制 | 翻译、冲突、时效或访问限制 |

每个关键数字、期限、门槛、处罚、程序节点和案例结论必须能够回到台账中的来源。

## 7. 覆盖性复核

完成初稿后，暂时不修改文字，单独检查：

- 是否只介绍原则而遗漏例外、豁免或相反情形；
- 是否只引用法规而遗漏实施指南、申报表或近期执法；
- 是否只写监管机关视角而遗漏交易执行和合同安排；
- 是否只列风险而没有给出可执行的管理动作；
- 是否因篇幅限制删除了会改变结论的重要条件；
- 是否用一个案例代表全部实践；
- 是否存在来源很多但都来自同一二级作者的伪多样性。

每一页在进入视觉制作前，记录其核心问题、结论、支持来源、限制条件和未覆盖事项。片面性会影响决定时，扩充、拆页或降低结论强度。

## 8. 冲突与不确定性

来源不一致时，不要静默选择一个答案。说明冲突来自法律层级、时间、事实前提、法域差异还是作者解释。若冲突可能影响管理层决策，在正文页提示，并在备注或附录记录细节。

## 9. 双语表达

第一次出现重要术语时给出英文原词及清晰中文解释。后续保持同一译法。法规、机关和案件名称优先保留官方原名；必要时提供便于中国管理层理解的中文简称，但不得暗示其为官方译名。
