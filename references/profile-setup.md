# 个人 PPT 配置向导

目标是把用户的工作经验和审美选择写成可复用规则。配置过程尽量使用选择、参考文件和样张，避免要求用户学习设计术语。

## 第一步：了解常用工作

询问并记录：

- 常见主题和法域；
- 主要受众，例如中国管理层、业务团队、董事会或法律团队；
- 主要目的，例如决策、风险提示、培训或项目汇报；
- 默认语言、页数范围、交付时限和模板；
- 对来源、引用、保密和人工复核的要求；
- 用户通常怎样判断一份 PPT 是否合格。
- 用户希望重点覆盖哪些法律维度，以及过去哪些页面曾被认为片面。

一次只问少量容易回答的问题。用户已经提供的信息不要重复询问。

## 第二步：提取视觉偏好

请用户提供一至三份喜欢的 PPT、PDF 或截图，也可以提供不喜欢的例子。分析时描述可观察特征：颜色、字体、标题层级、文字密度、留白、图表、图片、页眉页脚和来源位置。不要只记录“专业”“高级”等抽象词。

如果环境支持生成演示稿，制作四页小样：封面、规则解释、流程或时间线、管理建议。让用户指出保留和修改的部分。

## 第三步：保存个人配置

将结果写入用户指定位置。用户没有指定时，在其 PPT 工作目录创建一个个人工作区，不要把个人资料写进公共 Skill 目录。使用 [assets/workspace-config-template.md](../assets/workspace-config-template.md) 创建入口文件 `ppt-config.md`，再使用 [assets/profile-template.md](../assets/profile-template.md) 创建 `ppt-profile.md`。

个人配置应覆盖默认场景、内容标准、检索标准、视觉规则、交付格式和何时暂停确认。引用用户提供的模板路径时使用实际可访问路径；不要复制或公开机密模板。

个人工作区建议包含：

```text
我的PPT工作区/
├─ ppt-config.md
├─ ppt-profile.md
├─ 口径库/
│  ├─ _目录.md
│  └─ _反例.md
└─ 参考样张/
```

新 Agent 先读取 `ppt-config.md`，再按其中的实际路径加载配置。路径失效时向用户确认新位置，不在整台电脑中无边界搜索。

## 第四步：试运行

选择一个公开、虚构或已脱敏的小主题测试。检查配置是否真正影响大纲、样张和质量复核。把用户的修改转为明确规则，再更新配置。

配置完成后告诉用户可用的最短调用方式，例如：

> 按照我的 PPT 标准，制作一份面向中国管理层的某国监管指南。资料截至今天，先核验法源；只有发现重大范围问题时再问我。
