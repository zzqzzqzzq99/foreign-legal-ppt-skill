# 跨模型和 Agent 适配

Skill 提供工作标准，不会自动补齐宿主 Agent 缺少的能力。开始前检查并记录实际可用能力。

## 能力检查

- 能否联网搜索并打开官方网页；
- 能否读取 PDF、网页、Word、既有 PPT 和图片；
- 能否保留长任务的上下文和中间文件；
- 能否生成可编辑 PPTX；
- 能否渲染整套幻灯片并查看页面图片；
- 能否保存个人配置并在下次任务中读取；
- 是否能够访问用户获准使用的专业法律数据库。

缺少联网检索时，不得宣称已核验现行境外法律。缺少视觉输入或渲染时，不得宣称已检查最终版式。缺少持久文件或记忆时，应把议题地图、来源台账、大纲和个人风格文件作为显式附件传递。

## 模型使用方式

对速度优先或较轻量的模型，把任务拆成明确产物：

1. 形成议题地图；
2. 检索并填写来源台账；
3. 做覆盖性复核；
4. 形成逐页大纲；
5. 生成视觉样张；
6. 批量制作并渲染检查。

每一阶段读取上一阶段文件，不依赖模型“记得刚才做过什么”。不要在同一条指令中同时要求轻量模型完成广泛检索、法律判断、管理层改写、视觉设计和最终文件质检。

能力较强的模型可以一次连续执行多个阶段，但仍须生成同样的中间证据。模型更强不能替代法源、议题覆盖和人工专业判断。

## 失败诊断

页面内容片面时，按下列顺序排查：

1. 原始任务是否说明受众、目的、法域、截止日和重点问题；
2. 是否生成过议题地图，还是直接围绕标题搜索；
3. Agent 是否真正提供了联网、网页打开和文件读取能力；
4. 来源是否以官方一手资料为主，并覆盖例外和近期实践；
5. 中间资料是否完整传递给写作和制图阶段；
6. 模型是否因能力、推理强度或上下文限制提前收敛；
7. 用户的行业经验或交易目标是否尚未写入任务。

如果前五项没有完成，先修复流程和资料。流程完整后仍持续遗漏重大问题，再提高推理强度或更换模型。

## 最低人工输入

用户不需要逐页撰写内容，但应至少确认：

- 这份 PPT 给谁看；
- 看完需要作出什么决定；
- 哪个法域和时间点；
- 哪些问题绝对不能漏；
- 哪些结论属于用户经验、内部事实或需要律师判断。

这些问题构成 P0 前置约束，按 [upfront-briefing.md](upfront-briefing.md) 收集并保存为 `brief.md`。

Agent 应把用户后续补充沉淀到个人配置的"经验反馈"和用户工作目录的"口径库"，让同类任务逐步减少追问。
