# 使用者前置判断清单（Upfront Briefing）

目的：把受众、决策目的、不能遗漏的问题和是否涉及真实事项这四项**必须由使用者确认**的事情放在检索和制作之前。AI 可以帮助列出选项，但不得把建议冒充使用者已经作出的判断。
用法：新任务开始时，把本文件作为问卷交给使用者作答（一次少量问题；一次作答不完可分批）。作答结果写入任务的 `brief.md`，作为议题地图与大纲的种子。

## A. 最低前置判断（必须由使用者确认）

1. 这份材料给谁看？（最高管理层 / 业务条线 / 法务内部 / 外部对象）
2. 看完之后需要谁作出什么决定或动作？（知道风险即可 / 决定是否立项 / 决定申报与交易条款 / 培训留档）
3. 哪些问题绝对不能遗漏？
4. 这是一般介绍，还是涉及一项真实业务或交易？涉及真实事项时，再收集必要的业务连接点。

AI 不替使用者确认上述四项。使用者暂时不知道时，AI 可以列出候选答案帮助选择，并把未确认项标为假设。

## B. AI 先给默认建议

页数、语言、章节数量、视觉风格、引用位置、Q&A 卡和交付形式由 AI 根据场景提出默认方案。默认值应集中呈现，使用者只需修改不同意的部分。不要把可以安全推断的制作细节变成长问卷。

## C. 重点注意的方面（使用者提供种子，AI 负责展开）

请列出：老板/业务/律师**最担心、必答、不能漏**的三到五个问题或情形。例如：
- 是否有我司业务模式必然触发？触发判断按什么口径做？
- 哪些页面历史上容易做错或曾被指片面？（直接写：××类问题上次被批"类别不全面/口径不准"）
- 领导层能接受的结论强度（结论先行 / 给区间不给绝对判断）？

AI 把这些种子放进议题地图并补齐规则维度，但**不得**自行替换或删减使用者列出的必答项。

## D. 结构确认（P2，锁定后才制作）

1. 首次模式下，AI 给出 **一套推荐骨架 + 一套有实质差异的备选**；不要制造两个仅措辞不同的方案。
2. 核对模式下，优先复用上次结构，只列出需要改变的章节和原因。
3. 使用者选择或修改后，写入 `structure.md` 并锁定。
4. 锁定后如需改变叙事或增减章节，须回到使用者重新确认；中途自行改结构属于违规。

## E. 检索与制作阶段（P1/P3）的职责边界

| 事项 | 负责方 |
| --- | --- |
| 联网检索、法源核验、来源台账、议题地图展开 | AI |
| 管辖/门槛/例外分类的"规则结构还原"草稿 | AI 起草，使用者（律师）裁决 |
| 风险等级、结论强度、商业建议 | AI 只给草稿与依据，使用者裁决 |
| 叙事骨架、每页作用、结构锁定 | AI 提议，使用者裁决 |
| 版式、视觉、渲染、逐页质检 | AI |
| 对外口径与是否用于决策 | 使用者/负责律师 |

## F. 交付物清单（按任务性质取舍）

- `brief.md`（本清单作答结果）
- `structure.md`（已锁定的叙事骨架与确认记录）
- 议题地图 + 来源台账（含排除项与理由）
- 成品 PPTX + 每页来源短标
- `review-checklist.md`：按页列出 AI 已作但**需要律师裁决**的口径/结论/建议点；未裁决项默认标注"未复核，不作决策依据"
- `qa-card.md`（可选）：汇报现场预期追问 5–10 条 + 与页面口径一致的答案与依据定位

## G. 结束时一句话检查

"如果只看 brief.md 和 review-checklist.md，一个没参与制作过程的律师能不能独立复核这份 deck 的框架与判断？"——不能，则补材料，不进入交付。
